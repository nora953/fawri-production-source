## Verified current official Neon product constraints, not guessed provider settings

- Official current [Neon plans](https://neon.com/docs/introduction/plans) lists **Free = 6-hour instant restore window, capped at 1 GB of change history**; root-branch instant restore only; **1 manual snapshot**, **no scheduled/automatic snapshot backup on Free**. The current documentation distinguishes Launch/Scale scheduled backups from the Free tier; do not claim a 1-day/7-day daily schedule exists on this project.
- Official [Backup & restore](https://neon.com/docs/guides/backup-restore) confirms that the **Enhanced view** has a `Create snapshot` action; snapshots can be manually created **on root branches**. Instant restore has a data preview path and creates an old-backup branch; never click Restore without signed runbook approval.
- Neon states that snapshot one-step restore **can preserve the branch name and connection string yet changes the branch ID**; multi-step restore creates a new branch for inspection before swapping. This matters because Fawri's `scripts/lib/field002-r2-precommercial-source-admission.mjs` pins exact initial branch ID `br-holy-waterfall-b993zglb`. It MUST reject an unexpected branch after any restore, even if the user-facing URL still connects. Re-attest new ID, source and actual SQL role/RLS before any traffic. **Do NOT silently update branch pins or classify restored merchant data as first-launch fresh-schema-only.**
- Manual snapshots preserve database data/DDL but do not independently prove backups of third-party Meta provider state, webhook delivery, uploaded images, payment provider data or application secrets. A successful SQL restore alone cannot close `P0-HOSTED-RECOVERY`.
