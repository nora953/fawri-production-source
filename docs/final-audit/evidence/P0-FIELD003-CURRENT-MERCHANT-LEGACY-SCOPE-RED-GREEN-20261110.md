# P0 FIELD003 — current merchant incident must protect misclassified historic OPENED audit key

**Date:** 2026-11-10. **Scope:** one real source disclosure, **RED → GREEN** on actual disposable PostgreSQL + mounted full Express HTTP. **Release:** NO-GO; parent P0-ACCESS-FULL-ROLE-PRIVACY-MATRIX OPEN.

## Reproduced real negative

Historical early-warning SQL OPENED record can retain an incident key with a tenant ID yet lose both durable `audit_events.merchant_id` and JSON `metadata.scope='merchant'` / merchant fields. The active merchant evaluation still correctly identifies the same `merchant-channel-errors:<merchant-id>` incident as merchant-scoped. Before this fix `buildHistory` used *only* historical rows to classify its key; `syncEarlyWarningIncidentHistory` passed only `Set(currentByKey.keys())`. As a result the response for an authorized admin with `view_logs` but no `view_merchants` could return that tenant-bearing historical key as a public/system incident. This is a reproducible synthetic legacy-drift condition, **not evidence of a confirmed external breach**.
