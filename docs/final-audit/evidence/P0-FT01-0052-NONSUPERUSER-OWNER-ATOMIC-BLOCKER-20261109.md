[Initial actual failure #42578455707](https://github.com/nora953/fawri-production-source/actions/runs/42578455707) proved the committed 0052 line `ALTER FUNCTION public.fawri_sequence_merchant_deleted() OWNER TO fawri_cashier_retirement_owner` fails with PostgreSQL **SQLSTATE 42501: `must be able to SET ROLE "fawri_cashier_retirement_owner"`**. This is not an intermittent CI error and not a lack of schema files. Drizzle runs the entire fresh 53-step canonical sequence in a single transaction; after this failure the migration ledger count was **zero**, not 52, proving the expected all-or-none rollback on the experimental empty database.

A further **in-memory disposable-only** alteration tested the apparent workaround `GRANT fawri_cashier_retirement_owner TO CURRENT_USER WITH SET TRUE, INHERIT FALSE` immediately before OWNER change, with `REVOKE` immediately after. [Actual negative PG18 run #42579436613](https://github.com/nora953/fawri-production-source/actions/runs/42579436613) failed at **SQLSTATE 42501: `permission denied to grant role "fawri_cashier_retirement_owner"`**. Therefore merely adding a temporary `GRANT` to the current `CREATEROLE` owner is **not a verified or acceptable workaround**. The variant was never written into the canonical `lib/db/drizzle/0052...` SQL, whose reviewed SHA256 remains `aaf7ee97fbdef0c1b4600e905216117ee8ff89f31ccd67d783ab61a9c4bd9b8e`.

The non-superuser gate has since been rewritten to **expect exact 42501 denials** for both original and experimental variants, and to assert **zero Drizzle ledger rows, zero retirement owner role, and zero SECURITY DEFINER function residue** after each atomic rollback. This protects future developers from claiming a normal Neon `fawri_owner` can apply the 0052 as-is. The final CI result must be cited separately after completion; do not mark source-green before evidence.
