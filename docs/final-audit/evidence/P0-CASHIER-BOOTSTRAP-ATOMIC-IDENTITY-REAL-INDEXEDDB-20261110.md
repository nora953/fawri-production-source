# P0 CASHIER-SYNC-SEQUENCE-001 — initial device bootstrap identity overwritten by concurrent browser tabs (RED → GREEN)

**Checkpoint:** 2026-11-10. **Scope:** one **confirmed source race**, source-corrected on the active PR branch and demonstrated in real Chromium+IndexedDB. **Not** physical-device, cross-device hosted sequence, power-loss, restore or production-release acceptance.

## RED — real first-launch identity collision

The existing `getOrCreateCashierDeviceIdentity` in `artifacts/fawri/src/lib/cashierOperatorSessionRuntime.ts` opened one **readonly** transaction to discover absent `fawri-cashier-bootstrap-v1/identity/default`, then later opened a **separate readwrite** transaction and unconditionally stored a newly generated `local_merchant_id` / `device_id`. Multiple cash-register tabs (or requests within one tab) could see the same empty state and each generate different device identities. Only the last write survived; other callers could use orphaned local identity keys for their newly initialized storage. No actual customer loss is established; this was reproduced using synthetic fresh-profile storage.

- **Added real-browser test** [`f0d4bc9c`](https://github.com/nora953/fawri-production-source/commit/f0d4bc9c0a98801a254c62ae27c5411d69531b32), [workflow wiring `97ca71d9`](https://github.com/nora953/fawri-production-source/commit/97ca71d982ed04aad04687be063cb54f28eba729).
- **Real Chromium RED** [P0 cashier IndexedDB browser regression #42883953195](https://github.com/nora953/fawri-production-source/actions/runs/42883953195), **COMPLETED FAILURE on the NEW negative test**. Browser launched **2 same-origin tabs** against a fresh test-only deleted bootstrap DB and made **48 concurrent calls** to the actual exported production identity creator: **31 different `local_merchant_id|device_id|created_at` tuples**, rather than one. Exact failure: `P0_BOOTSTRAP_CONCURRENT_CREATE_LOST_IDENTITY {"distinct_created_identifiers":31,"instances":48,"persisted_match":true}`. Earlier native browser sale/outbox/station tests in the same run were green.

## GREEN — one native transaction for read and conditional create

- **Production code fix** [`14b4403d`](https://github.com/nora953/fawri-production-source/commit/14b4403df924906392f4e1926ab3716a206ccfc1): the existing creator now opens **one readwrite IndexedDB transaction** for both `store.get('default')` and conditional `store.put(identity)`. Concurrent callers serialize the creation under the browser's IndexedDB transaction scheduler; if another caller has already stored a complete identity, the next returns the existing record rather than generating and overwriting an incompatible one. The transaction completion is awaited on both existing-identity and new-identity paths. No reset, new credential, re-pair, sequence manipulation, or deletion of financial records.
- **Real Chromium GREEN on source code SHA `14b4403d`**: [browser regression #42884253190](https://github.com/nora953/fawri-production-source/actions/runs/42884253190), job `130068282143`, **COMPLETED SUCCESS**. Exact native trace:
  `P0_CASHIER_BOOTSTRAP_ATOMIC_CREATE_REAL_INDEXEDDB {"nativeIndexedDb":true,"realChromium":true,"independentTabs":2,"simultaneousCallers":48,"uniqueIdentities":1,"stableAfterReload":true,"serverAcceptance":false,"physicalDeviceAcceptance":false}`.

  **Trace interpretation clarification:** this first run asserted identical returned identities and fresh repeated reads from both tabs, **not a browser page reload**; the trace field `stableAfterReload` was too broad and is corrected to `stableAcrossBothTabs` in test-only [`6e39af3e`](https://github.com/nora953/fawri-production-source/commit/6e39af3e627d13a4993e9c2f70cf1eab0d902f79). It does not invalidate the proven 48-caller atomicity.
