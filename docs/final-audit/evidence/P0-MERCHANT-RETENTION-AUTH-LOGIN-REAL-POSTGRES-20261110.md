**Date:** 2026-11-10. **Scope:** a bounded actual PostgreSQL functional acceptance of the already fixed retention-account reactivation logic; not hosted or commercial identity admission. Parent `P0-RETENTION-PRIVILEGED-DELETION-POLICY` remains **OPEN**.

## Risk and bounded source correction

The earlier [source correction `5b199e72`](https://github.com/nora953/fawri-production-source/commit/5b199e72a04d9d1dfb0bad10c9aa46c57c8fc8c9) prevented `refreshMerchantRetentionPostgres` from treating an unapproved subscription's future `expires_at` as sufficient proof to restore a retention-suspended merchant account. Only an explicitly `active` or `replies_exhausted` subscription with valid future expiry now permits restoration. A future-only `pending_activation`, `suspended`, or `expired` record cannot reset merchant/account retention protection.

Previous [source-executing **5/5** #42750820065](https://github.com/nora953/fawri-production-source/actions/runs/42750820065) used a synthetic SQL transaction recorder and **did not** prove database behavior. This checkpoint closes the **bounded real SQL execution gap** without claiming a hosted role/HTTP acceptance.
