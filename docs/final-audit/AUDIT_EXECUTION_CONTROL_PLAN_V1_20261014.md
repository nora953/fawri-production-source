P0: tenant/RLS/authorization; owner/admin/support/emergency access; money and provider callbacks; cashier offline license/grace, duplicate operation, sync/outbox, stock concurrency; data deletion, recovery, backup/PITR; secrets/production readiness. ## 3. Efficient execution batches
A) One-time inventory reconciliation and source-SHA snapshot. B) Select 5–12 distinct **unverified high-risk** cases per batch; group by shared fixture/runtime to amortize setup. C) Run cheapest valid evidence first (source → targeted unit → targeted SQL/HTTP → native browser → staging), never promote cheap proof into higher proof layer. D) Reuse green evidence only if same code/config, assertion, proof layer and environment contract; record stale evidence separately. E) On failure, isolate a minimal reproduction once; compare to canonical ISSUES.md; create new finding only if distinct invariant/root cause. F) Stop retries after 1 controlled rerun unless failure is nondeterministic and a specific hypothesis justifies a second; preserve original failure. G) Never trigger full 33-workflow matrix just to update audit markdown. Prefer existing CI run and narrow targeted workflows; batch updates at end. H) Separate harness/infrastructure failure from product failure. I) Do not write large repetitive ledger summaries; one canonical per-case record and a concise append-only checkpoint with links.

## 4. Immutable evidence contract
Every case result MUST record case_id, source commit/tree SHA, test harness SHA, command/workflow run/job URL or ID, environment and role/DB attestation, timestamp, assertion expected/actual, PASS/FAIL/BLOCKED/NOT_RUN/TRIAGE, limitations, artifact/log/screenshot path, and canonical issue ID if any. For failures record reproduction steps, impact, severity, affected tenant/role, confidence, observed vs inferred, synthetic vs real, and scope exclusions. Secrets/PII must be redacted; never upload real customer data. Screenshots alone do not prove backend permissions. Never claim a file/commit exists without verifying successful GitHub write.
